# Header

The Header component functions as a top-level navigation element for digital services across government departments and public sector organisations. It offers users a consistent and recognisable interface that builds trust, supports a unified brand identity, and delivers key navigation tools. Originally referred to as the GOV.IE masthead, this component is designed to signal to users that they are engaging with an official government service while providing easy access to essential site-wide features. It is adaptable for use beyond GOV.IE, supporting a broad range of departmental and agency websites. Build it from primitives in `@ogcio/design-system-react/next` so services keep consistent Gov.ie styling while controlling structure and accessibility themselves.

## Structure

Compose the header from these primitives:

- `Header` - semantic `<header>` landmark
- `HeaderSection` - full-width band with a built-in content container (`variant="primary"` | `"utility"`, optional `appearance`)
- `HeaderLogo` - brand mark container
- `HeaderTitle` - service or application name
- `HeaderNav` - navigation list (`ariaLabel` required)
- `HeaderNavItemLink` - navigational link
- `HeaderNavItem` - action button (search, menu, tools)
- `HeaderNavItemSeparator` - vertical divider between nav items

Typical layout:

1. **Utility section** (`variant="utility"`) - language switchers and secondary tools (hidden below the `lg` breakpoint by default).
2. **Primary section** (default) - logo and/or title, plus primary navigation.

```jsx
import {
  Header,
  HeaderSection,
  HeaderLogo,
  HeaderTitle,
  HeaderNav,
  HeaderNavItem,
  HeaderNavItemLink,
  HeaderNavItemSeparator,
} from '@ogcio/design-system-react/next';
import { LogoWhite } from '@ogcio/design-system-react/logos';
import { SearchIcon } from '@ogcio/design-system-react/icons';

<Header ariaLabel="Site header">
  <HeaderSection variant="utility">
    <HeaderNav ariaLabel="Utility navigation">
      <HeaderNavItemLink href="#">Gaeilge</HeaderNavItemLink>
      <HeaderNavItemLink href="#">English</HeaderNavItemLink>
    </HeaderNav>
  </HeaderSection>

  <HeaderSection>
    <HeaderLogo>
      <LogoWhite />
    </HeaderLogo>
    <HeaderTitle>Application Title</HeaderTitle>
    <HeaderNav ariaLabel="Primary navigation">
      <HeaderNavItemLink href="#">News</HeaderNavItemLink>
      <HeaderNavItemLink href="#">Departments</HeaderNavItemLink>
      <HeaderNavItemLink href="#">Services</HeaderNavItemLink>
      <HeaderNavItemSeparator />
      <HeaderNavItem ariaLabel="Toggle site search">
        Search
        <SearchIcon />
      </HeaderNavItem>
    </HeaderNav>
  </HeaderSection>
</Header>;
```

`HeaderSection` provides the content container - use `maxWidth` to cap width, and `appearance="light"` when you need a light header band.

## Usage

Use the header at the top of every page on your service. Identify the service with a logo and/or short title, then add only the top-level navigation and tools users need.

### Appearance

Pass the same `appearance` to each `HeaderSection` so utility and primary bands stay aligned:

- **Default** - dark surface, light text
- **Light** - light surface, dark text (pair with dark logos such as `LogoBlack` / `LogoHarpBlack`)

### Logo and title

- Put brand assets inside `<HeaderLogo>`.
- Keep `<HeaderTitle>` short so it truncates cleanly on smaller viewports.
- For a home link, wrap the link in `HeaderLogo` and give it an accessible name.

### Navigation

- Put language and secondary tools in the utility `HeaderSection`.
- Put main links in the primary `HeaderSection` inside `<HeaderNav>`.
- Use `HeaderNavItemLink` for destinations and `HeaderNavItem` for actions (for example search).
- Separate groups with `HeaderNavItemSeparator` when needed.
- Use `visible` on nav items when something should only show from a breakpoint (for example `visible="lg"`).

## Do

- Use one header per page.
- Give every `<HeaderNav>` a distinct `ariaLabel` (for example `"Primary navigation"` and `"Utility navigation"`).
- Identify the service with a logo and/or concise title.
- Keep primary navigation to a small set of top-level destinations.
- Use `HeaderNavItem` for interactive tools such as search, drawer, and toggling languages.

## Don't

- Use a long service title that crowds out navigation.
- Cram many primary links, language options, and tools into a single undifferentiated row.
- Put language switchers in the primary nav when a utility section is available.
- Omit landmark labels on `<Header>` or `<HeaderNav>`.
- Use more than one header on a page.
- Imitate the GOV.IE header on third-party services without a clear distinction.

## Accessibility

The composable Header does not inject landmark labels or translations. You own the accessible names, current-page state, and language markup.

### Landmarks

- Set `ariaLabel` on `<Header>` so the banner is distinguishable in the landmark list.
- Give every `<HeaderNav>` a distinct `ariaLabel` (for example `"Primary navigation"` and `"Utility navigation"`). `ariaLabel` is required on `HeaderNav`.
- Use one `<Header>` per page. Do not nest extra banner landmarks inside it.

### Logo and title

- `<HeaderLogo>` is a layout wrapper, not a link. Put a `<Link>` inside it and give that link an accessible name, for example `ariaLabel="Gov.ie home"`.
- Give logo images `alt` text, or mark them decorative if the wrapping link already names the destination.
- `<HeaderTitle>` styles the service name. It is not a heading element — keep the page `<h1>` in the main content.

### Navigation

- Use `ariaCurrent="page"` on the `HeaderNavItemLink` for the current page.
- For language switchers, set `lang` to the language of the link text (for example `lang="ga"` on "Gaeilge") so assistive technology pronounces it correctly.
- Use `HeaderNavItem` for actions such as search or menu, not links.
- When a nav item controls a panel, set `ariaExpanded` and `ariaControls` to the panel id, and keep the accessible name stable. Name the panel itself as well.
- Provide `ariaLabel` when the visible text is missing or insufficient (icon-only controls, or "Search" that actually toggles a panel).
- `<HeaderNavItemSeparator>` is decorative (`aria-hidden`). Do not rely on it to convey meaning.
- `visible` and the utility section use `display: none` below their breakpoints, so hidden items leave the accessibility tree. Do not leave a destination reachable only from a hidden control.

```jsx
<Header ariaLabel="Site header">
  <HeaderSection variant="utility">
    <HeaderNav ariaLabel="Utility navigation">
      <HeaderNavItemLink href="/ga" lang="ga">
        Gaeilge
      </HeaderNavItemLink>
      <HeaderNavItemLink href="/en" lang="en" ariaCurrent="true">
        English
      </HeaderNavItemLink>
    </HeaderNav>
  </HeaderSection>

  <HeaderSection>
    <HeaderLogo>
      <Link appearance="light" href="/" ariaLabel="Gov.ie home">
        <LogoWhite />
      </Link>
    </HeaderLogo>
    <HeaderNav ariaLabel="Primary navigation">
      <HeaderNavItemLink href="/news" ariaCurrent="page">
        News
      </HeaderNavItemLink>
      <HeaderNavItem
        ariaLabel="Toggle site search"
        ariaExpanded={searchOpen}
        ariaControls="site-search"
      >
        Search
        <SearchIcon />
      </HeaderNavItem>
    </HeaderNav>
  </HeaderSection>
</Header>
```

## Migration guide

The Header from `@ogcio/design-system-react` is **deprecated**. Migrate to the composable primitives from `@ogcio/design-system-react/next`.

There were two deprecated surfaces, and `Header` from the main package switched between them:

1. **Header (Deprecated)** — props such as `title`, `logo`, `items`, and `secondaryLinks`. ([Storybook](/storybook-react/docs/layout-header-legacy-header-deprecated--docs))
2. **Header (Legacy)** — children such as `HeaderLogo`, `HeaderTitle`, `HeaderPrimaryMenu`, and `HeaderSecondaryMenu`. `Header` used this API when you did not pass Header (Deprecated) props - ([Storybook](/storybook-react/docs/layout-header-legacy-header-legacy--docs))

<Alert>
  The **Header (Deprecated)** API used the following props. If you passed any of these, refer
  to **Header (Deprecated)**. Otherwise, refer to **Header (Legacy)** as your starting point.

`title`, `logo`, `appearance`,
`addDefaultMobileMenu`, `mobileMenuLabel`, `showMenuLabel`, `items`,
`secondaryLinks`, and `showTitleOnMobile`.

</Alert>

`HeaderLogo` and `HeaderTitle` are new components designed for the composable architecture with the **same names** as their legacy counterparts — import them from `@ogcio/design-system-react/next`, **not** from `@ogcio/design-system-react`.

```jsx
// Before — Header (Deprecated) or Header (Legacy)
import {
  Header,
  HeaderLogo,
  HeaderTitle,
  HeaderPrimaryMenu,
  HeaderSecondaryMenu,
  HeaderMenuItemLink,
  HeaderMenuItemButton,
  HeaderMenuItemSeparator,
} from '@ogcio/design-system-react';

// After
import {
  Header,
  HeaderSection,
  HeaderLogo,
  HeaderTitle,
  HeaderNav,
  HeaderNavItem,
  HeaderNavItemLink,
  HeaderNavItemSeparator,
} from '@ogcio/design-system-react/next';
```

**Why migrate:**

- Layout flexibility: you own sections, navigation, and logo placement.
- Precise semantics and a11y: set `ariaLabel` and navigation labels yourself.
- Clearer JSX: named children (`HeaderSection`, `HeaderLogo`, `HeaderNav`) instead of opaque `items` / `secondaryLinks` props or Header (Legacy) menu primitives.

**After** — the same composable structure for either starting point:

```jsx
import {
  Header,
  HeaderSection,
  HeaderLogo,
  HeaderTitle,
  HeaderNav,
  HeaderNavItem,
  HeaderNavItemLink,
  HeaderNavItemSeparator,
  Link,
} from '@ogcio/design-system-react/next';
import { LogoWhite } from '@ogcio/design-system-react/logos';
import { SearchIcon } from '@ogcio/design-system-react/icons';

<Header ariaLabel="Site header" dataTestId="header">
  <HeaderSection variant="utility">
    {/* former secondaryLinks / HeaderSecondaryMenu */}
    <HeaderNav ariaLabel="Utility navigation">
      <HeaderNavItemLink href="#">Gaeilge</HeaderNavItemLink>
      <HeaderNavItemLink href="#">English</HeaderNavItemLink>
    </HeaderNav>
  </HeaderSection>

  <HeaderSection>
    <HeaderLogo>
      <Link href="/" appearance="light" ariaLabel="Homepage">
        <LogoWhite />
      </Link>
    </HeaderLogo>
    <HeaderTitle>Application Title</HeaderTitle>
    <HeaderNav ariaLabel="Primary navigation">
      {/* former items / HeaderPrimaryMenu */}
      <HeaderNavItemLink visible="lg" href="#">
        News
      </HeaderNavItemLink>
      <HeaderNavItemLink visible="lg" href="#">
        Departments
      </HeaderNavItemLink>
      <HeaderNavItemLink visible="lg" href="#">
        Services
      </HeaderNavItemLink>
      <HeaderNavItemSeparator visible="lg" />
      <HeaderNavItem visible="lg" ariaLabel="Toggle site search">
        Search
        <SearchIcon />
      </HeaderNavItem>
    </HeaderNav>
  </HeaderSection>
</Header>;
```

Key differences when transforming:

1. **Two sections, in visual order** - utility content (`secondaryLinks` or `<HeaderSecondaryMenu>`) moves into `<HeaderSection variant="utility">`. Logo, title, and primary nav share the default `<HeaderSection>`. Header (Legacy) reordered children for you; write the utility section first.
2. **Navigation is explicit** - replace `items` or `<HeaderPrimaryMenu>` with `<HeaderNav>` children: `HeaderNavItemLink` for links, `HeaderNavItemSeparator` for dividers, and `HeaderNavItem` for actions.
3. **Appearance lives on sections** - Header (Deprecated) `appearance` and Header (Legacy) `variant` become `appearance` on each `HeaderSection`. Pass the same value to every section.
4. **Logo and title are children** - place `<HeaderLogo>` next to `<HeaderTitle>`. Neither accepts `href`; place a `<Link>` inside.
5. **Accessibility is explicit** - set `ariaLabel` on `<Header>` and a distinct `ariaLabel` on every `<HeaderNav>`. Both deprecated forms applied a default header label.
6. **Slots and panels are your own** - Header (Deprecated) `itemType: 'slot'` drawers, Header (Legacy) `<HeaderMenuItemButton>` panels, and `<HeaderSlotContainer>` are not built in. Use `<HeaderNavItem>` with `onClick` / `ariaExpanded` / `ariaControls` and render the panel yourself.
7. **Mobile menu is composed** - `addDefaultMobileMenu` is gone. Add a `<HeaderNavItem>` that opens your own drawer. Use `visible` to match former `showItemMode` values (see the table above).
8. **Navigation item spacing** - the composable API uses a 16 pixel gap between items in every section.

### Migrating the logo

Header (Deprecated) accepted `href`, `alt`, `imageLarge`, `imageSmall`, and `external`, and rendered a linked logo when `href` was set. Header (Legacy) `HeaderLogo` accepted `href` and rendered an `<a>`.

In the composable API, `HeaderLogo` only handles positioning. Render the image yourself:

```jsx
// Before — Header (Deprecated)
<Header
  logo={{
    href: '/',
    alt: 'Gov.ie Logo',
    imageLarge: '/logo-desktop.svg',
    imageSmall: '/logo-mobile.svg',
    external: false,
  }}
  title="Application Title"
/>

// Before — Header (Legacy)
<HeaderLogo href="/">
  <LogoWhite />
</HeaderLogo>

// After
  <HeaderLogo>
    <Link appearance="light" href="/" ariaLabel="Go to the home page">
      <LogoWhite />
    </Link>
  </HeaderLogo>
```

- For the default (dark) header, use `LogoWhite` / `LogoHarpWhite`. For `appearance="light"`, use `LogoBlack` / `LogoHarpBlack`.
- For custom assets, use your own `<img>` or `<picture>` with `alt` text.
- To keep a home link (optional), wrap the logo in `<Link>` yourself and set an accessible name. Use `external` on `<Link>` if the destination is off-site.
- The same applies to Header (Legacy) `<HeaderTitle href="…">` — wrap `<Link>` in `<HeaderTitle>` instead.
- `HeaderLogo` does not add a link, alt text, or image for you. Wrap a `<Link>` inside.

### Related layout pieces

- `HeaderSection` centres and pads its content with a built-in [Container](/components/library/container/design/) — use `maxWidth` to cap the content width (`maxWidth="full"` replaces `fullWidth`).
- Pass the same `appearance` to each `HeaderSection` so utility and primary bands stay aligned.
- Use `visible` on nav items when something should only show from a breakpoint (for example `visible="lg"`).
